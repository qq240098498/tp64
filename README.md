# tp64 接口调试与用例回归对比平台

一个本地小工具：在页面上填好请求方式、目标地址、请求头与请求内容，点发送就把请求真的发出去，结果区显示响应状态、耗时、响应头与响应内容，失败时显示失败原因；每发送一次都会留下一条执行记录，可以按目标地址、结论与时刻区间筛选巡检；常用的请求可以存成用例，之后一键回填再发一遍。

服务端内置了几个示例接口，本机不填任何外部地址也能直接试出完整效果。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件直接由后端静态目录提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5064>

端口固定为 `5064`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 请求区填好请求方式与目标地址，需要时再补请求头与请求内容
2. 点发送请求，结果区出现状态码、耗时、内容大小、响应头与响应内容；内容能解析成结构化数据时按层级铺开显示，也可以切到原始文本
3. 目标地址填成不通的地址时，结果区给出失败原因，例如找不到主机、端口拒绝连接、等待超过上限
4. 页面下方的执行记录区按时刻从新到旧列出每一次发送：目标地址、请求方式、结论、耗时、时刻，失败的还能看到可读失败原因；可以按目标地址关键字、结论与时刻区间筛选，多个条件叠加取交集
5. 想要留着下次再用，就填上用例名称点保存为用例
6. 用例列表里点回填，用例保存下来的内容会写回请求区，可以直接点发送请求重发；点详情看完整内容，点删除会先确认

目标地址有两种写法：以 `/` 开头表示本机内置示例接口，例如 `/demo/echo`；也可以填写 `http://` 或 `https://` 开头的完整地址。请求头留空的行会被忽略，同名请求头重复填写会被拒绝并指出是第几行。

## 内置示例接口

| 名称     | 请求方式 | 路径                        | 说明                                                                 |
| -------- | -------- | --------------------------- | -------------------------------------------------------------------- |
| 回声接口 | 任意     | `/demo/echo`                | 把收到的请求方式、请求头、查询参数与请求内容原样回显                 |
| 报错接口 | 任意     | `/demo/status?code=500`     | 按地址里的取值返回对应状态码，取值需要在 200 到 599 之间             |
| 列表接口 | GET      | `/demo/items?page=1&size=3` | 返回带分页信息的条目列表，每页条数最多 20 条                         |
| 延迟接口 | 任意     | `/demo/slow?ms=1500`        | 等待指定毫秒数之后再返回，取值需要在 0 到 10000 之间                 |

页面的请求区里列出了这四个接口，点填入请求区就会把示例内容写好，直接点发送请求即可。示例调用也可以在地址上带参数：回声接口带查询参数会一并回显，报错接口把 `code` 改成 404 或 500 能看到不同的失败状态，列表接口把 `page` 与 `size` 调大能看到更长的列表，延迟接口把 `ms` 调到 3000 能看到更明显的等待反馈。

## 当前已具备的能力

- 请求区填写草稿：请求方式、目标地址、请求头（可增行、可删行）、请求内容、用例名称
- 真正发送请求：由服务端代发，本机示例接口与外部完整地址都支持
- 结果区展示：响应状态与状态说明、耗时、内容大小、目标地址、响应头逐行展示、响应内容按结构或原始文本查看
- 失败反馈：网络层失败给出可读原因与详细信息，请求内容与请求方式不匹配、目标地址格式不对等问题会标到对应输入项上
- 发送等待反馈：等待期间结果区显示等待提示，发送按钮显示发送中
- 执行留痕：每发送一次就落一条执行记录，记下目标地址、请求方式、结论、耗时与发生时刻；网络层未完成或目标返回 4xx/5xx 都记为失败，并保存可读的失败原因与技术详情
- 执行记录巡检：记录按时刻从新到旧排列（同一时刻用记录 id 兜底决胜，顺序确定），支持按目标地址关键字、结论与时刻区间筛选，多个条件叠加时取交集，同一组条件反复筛选顺序完全一致
- 保存用例：保存前校验请求方式取值、目标地址格式、请求头名称与重复情况、请求内容是否为合法 JSON，出错时页面会指出是哪一项的问题
- 用例列表：展示全部用例，标记出保存时写的是本机示例接口地址的条目，可按创建时间从新到旧排列，支持手动刷新
- 回填用例：把用例保存下来的请求方式、目标地址、请求头与请求内容写回请求区，可直接重发
- 查看用例：在详情区展示该用例保存下来的地址、请求头、请求内容与保存时间，详情区也能直接回填
- 删除用例：删除前先确认，删除后列表与详情同步更新

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "cases": [...], "executions": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。旧数据文件没有 `executions` 字段时会在首次载入时自动补成空列表，无需手工迁移。

## 接口一览

| 方法   | 路径            | 说明                         |
| ------ | --------------- | ---------------------------- |
| GET    | /api/health     | 服务状态检查                 |
| GET    | /api/demos      | 内置示例接口清单             |
| POST   | /api/send       | 按填写的草稿发送一次请求，并补一条执行记录 |
| GET    | /api/executions | 获取执行记录列表（按时刻从新到旧）         |
| GET    | /api/cases      | 获取用例列表                 |
| GET    | /api/cases/:id  | 获取单条用例                 |
| POST   | /api/cases      | 保存一条用例                 |
| DELETE | /api/cases/:id  | 删除一条用例                 |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。发送接口的返回值里带上发送是否完成、状态码、耗时、响应头与响应内容，目标不可达时同样以正常返回值描述失败原因，页面按失败外观展示。
